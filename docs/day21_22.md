## 统一接口

```text
MarketDataProvider
├── get_quote(symbol, as_of) -> Quote | None
└── get_bars(
      symbol,
      as_of,
      timeframe,
      limit,
      include_incomplete=False,
    ) -> list[Bar]
```

`Quote` 保存市场报价时间 `quoted_at` 和系统接收时间 `received_at`。

`Bar` 保存 `start_at`、`end_at`、`updated_at`、`received_at`、OHLCV、完成状态和复权方式。完成的 Longbridge Bar 使用 `end_at` 作为 `updated_at`，不会因为本次下载时间较晚而被历史 `as_of` 错误过滤；未完成 Bar 使用本次快照的接收时间。

Fixture Bar 继续使用统一的简单规则：

```python
bar.updated_at <= as_of
and (bar.is_complete or include_incomplete)
```

## Longbridge 适配器

```text
stock_agent/market/
├── schemas.py
├── provider.py
├── errors.py
└── longbridge/
    ├── config_factory.py
    ├── longbridge_mapper.py
    └── longbridge_provider.py
```

职责划分：

- `config_factory.py` 从 Longbridge 环境变量创建 `QuoteContext`；
- `longbridge_mapper.py` 转换 symbol、Quote、Period 和 Bar；
- `longbridge_provider.py` 调用 SDK、排序、限制数量并转换供应商异常；
- 正常无数据返回 `None` 或空列表；
- `OpenApiException` 转换为 `MarketDataProviderError`。

Provider 接收任意美股 ticker，并在调用 SDK 时转换为 `ticker.US`。上层拿到的仍是项目内部 ticker，不依赖预置公司列表。

默认日线请求会多取一根数据，再过滤尚未完成的当前 Bar，从而保证正常情况下仍能返回调用方要求的 60 根已完成日线。完成 Bar 的 `data_mode` 是 `historical`，未完成 Bar 和 Quote 的 `data_mode` 是 `live`。

Longbridge 没有在当前 Quote 响应中提供可直接映射的延迟标志，因此 `Quote.is_delayed` 保留为 `None`，不把未知状态写成 `False`。

我在 Market Data 层没有让业务代码直接依赖具体行情供应商，而是先定义了统一的 MarketDataProvider 接口，以及自己的 Quote 和 Bar 数据模型。

具体实现上，目前接的是 Longbridge OpenAPI。Provider 负责调用 SDK，而 mapper 负责把 Longbridge 的 NVDA.US、SecurityQuote、Candlestick、Period 等供应商字段转换成系统内部统一模型。这样未来如果切换到 Futu 或其他数据源，上层 Agent 和技术指标模块不需要修改。

时间语义上，我区分了市场时间和系统接收时间，比如 Quote 有 quoted_at 和 received_at，Bar 有 start_at/end_at/received_at，避免把网络响应时间误当成市场数据时间。

另外我把“正常无数据”和“供应商异常”分开处理：正常无数据返回 None 或空列表，而 API 失败转换成自己的 MarketDataProviderError，不会让 Agent 把供应商故障误判成股票没有数据。

历史 K 线目前支持至少 60 个交易日，并保留是否包含当前 incomplete Bar 的能力，为后面的 MA、ATR、涨跌幅和当前盘中结构分析做准备。
