## Day21 数据契约

```text
MarketDataProvider
├── get_quote(symbol, as_of) -> Quote | None
└── get_bars(
      symbol,
      as_of,
      timeframe,
      limit,
      include_incomplete=False,
    ) -> list[Bar]
```

`Quote` 保存：

- 标准 ticker；
- Decimal 价格和币种；
- `quoted_at` 市场报价时间；
- `received_at` 系统接收时间；
- session、data mode、延迟状态和来源。

`Bar` 保存：

- timeframe 与 OHLCV；
- `start_at` / `end_at`；
- `updated_at` 市场快照更新时间；
- `received_at` 系统接收时间；
- completed 状态、复权口径、来源和 data mode。

所有具体时间必须带时区。

## Point-in-time 规则

Quote 只有在以下条件成立时才能返回：

```text
quote.received_at <= as_of
```

默认 Bar 查询只返回：

```text
bar.is_complete
and bar.updated_at <= as_of
```

调用方显式设置 `include_incomplete=True` 后，未完成 Bar 只需满足：

```text
bar.updated_at <= as_of
```

Bar 统一按市场数据更新时间过滤，不使用本次系统获取或落库的 `received_at` 过滤。

## 动态 ticker

Provider 对输入执行首尾空格清理和大写标准化。同一个接口可以查询 NVDA、AMD 或其他 Provider 已覆盖的 ticker，不使用公司白名单。

证券 ticker 与 SEC CIK 保持分离：Market Data 使用 ticker；SEC Document/Financial 使用发行人 CIK。

我在 Market Data 层没有让业务代码直接依赖具体行情供应商，而是先定义了统一的 MarketDataProvider 接口，以及自己的 Quote 和 Bar 数据模型。

具体实现上，目前接的是 Longbridge OpenAPI。Provider 负责调用 SDK，而 mapper 负责把 Longbridge 的 NVDA.US、SecurityQuote、Candlestick、Period 等供应商字段转换成系统内部统一模型。这样未来如果切换到 Futu 或其他数据源，上层 Agent 和技术指标模块不需要修改。

时间语义上，我区分了市场时间和系统接收时间，比如 Quote 有 quoted_at 和 received_at，Bar 有 start_at/end_at/received_at，避免把网络响应时间误当成市场数据时间。

另外我把“正常无数据”和“供应商异常”分开处理：正常无数据返回 None 或空列表，而 API 失败转换成自己的 MarketDataProviderError，不会让 Agent 把供应商故障误判成股票没有数据。

历史 K 线目前支持至少 60 个交易日，并保留是否包含当前 incomplete Bar 的能力，为后面的 MA、ATR、涨跌幅和当前盘中结构分析做准备。
