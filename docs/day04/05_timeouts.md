# 5. 单工具超时、任务总时限与预算

先在 backend/examples/timeout_cancel.py 离线练习，再整合到 structured_agent.py。

## 你来完成

1. 编写 async 模拟工具，用 asyncio.sleep 模拟慢速 I/O。
2. 使用 Python 3.11 的 asyncio.timeout，分别演示工具局部超时与整个任务总超时。
3. 总时限覆盖模型调用、工具等待、格式修复等完整流程，不在每轮重新开始计时。
4. 工具局部超时可转为 tool_timeout 结果交回模型；任务总超时直接结束整个任务。
5. 区分嵌套超时的归属，不能把任务总取消误判为某个工具超时并继续执行。
6. 保留 MAX_MODEL_ROUNDS=3、MAX_TOOL_CALLS=4；修复与最终结果生成也计入模型轮数。
7. 限制每次输出 token，并记录实际用量；不要把输出上限当作整个任务的总 token/费用硬上限。

## 注意

- 在 async def 内调用阻塞 SDK 或 time.sleep，仍会阻塞事件循环，超时可能不能及时执行。
- 本练习仅用可取消的异步等待验证；不要声称线程包装可强制终止底层同步调用。
- asyncio 超时依赖协作式取消和清理，不是强制杀进程的硬截止。
- 一次远端调用本地超时后，服务端仍可能完成并产生费用。

## 验收

快工具成功；慢工具触发局部超时；多个步骤累计超时触发总终态。
记录超时后后续模型/工具的调用次数为 0，不仅打印“超时”就算通过。
