# 第 6 步：执行工具并回传结果

实现位置：backend/examples/manual_agent.py。

## 你来完成

1. 每轮收到工具调用时，先把该轮 assistant 消息（包含完整 tool_calls）加入 messages。
2. 按顺序处理每个工具请求。调用第 3 步的 execute_tool，并保留 fixture/source/时间字段。
3. 成功结果包装为 {"ok": true, "data": 工具返回值}。
4. 可处理的错误包装为 {"ok": false, "error": {"code": 本地错误类别, "message": 安全说明}}。
5. 用 json.dumps(..., ensure_ascii=False) 把结果转成字符串。
6. 为每个工具调用追加一条消息：role="tool"、tool_call_id=该次调用的原始 ID、content=结果字符串。
7. 全部工具调用都有对应结果后，再携带更新后的 messages 请求模型。

## 关键约束

- 一轮可能有多个工具调用，不能只处理第一个。
- 结果用调用 ID 对应，而不是仅靠工具名称；同一个工具可能被调用多次。
- SDK 消息对象需要转换为接口接受的字典；保留必要的工具调用字段，参考已安装 SDK 的序列化方法。
- JSON 错误、未知工具、参数错误、工具拒绝公司应区分错误类别，不返回假成功数据。
- 无法识别的程序异常明确结束，不泄露原始响应、请求头或密钥。
- 今天不提供任何文件删除、代码执行或交易工具。

## 验收

手动构造一轮两个不同 ID 的工具请求，确认生成两条匹配的 tool 消息。
把其中一个请求改成非法参数，确认失败也有相应 ID 的错误结果，且该函数未被执行。
最终回答应明确“模拟报价”，不能把 100 美元说成实时或已核实的历史价格。
