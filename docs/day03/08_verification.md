# 第 8 步：事件记录与验收

实现位置：manual_agent.py 的记录逻辑，以及 backend/examples/verify_manual_agent.py 的离线验证。

## 记录要求

1. 用事件列表或逐行 JSON 记录 model_request、tool_requested、tool_succeeded、tool_failed、run_finished。
2. 记录轮数、工具调用 ID、白名单工具名、校验后的公司标识、fixture 结果、执行次数和终态。
3. 每轮记录模型耗时及可获得的 token 用量；用量缺失写明 unavailable，不编造为 0。
4. 每次运行分配 run_id。可使用 uuid.uuid4，方便区分多次运行。
5. 不记录 API Key、请求头、原始异常、模型内部推理或未经筛选的参数对象。未知工具名可记录为固定的 unknown_tool。
6. 保存演示记录到 docs/day03/ 下，标清 fixture、offline_simulation 或 real_api，不能把离线响应冒充真实模型。

## 离线验证

编写一个可以注入模拟模型响应的循环入口，或用 unittest.mock 替换模型调用。
验证脚本导入 manual_agent 时不得自动发起 API 请求。

至少检查：
- 正常工具请求 -> 执行 -> 按 ID 回传 -> 最终回答。
- 一轮多个工具调用的 ID 对应正确。
- 错误 JSON、非字典参数、空字段、额外字段、未知工具被拒绝，工具执行次数为 0。
- AAPL 通过格式校验，但函数抛 ValueError，并生成工具失败结果。
- 工具预算、模型轮数预算确实阻止后续调用（检查调用计数，不只看打印文案）。
- 响应无 choices、空正文、输出截断或调用 ID 异常，不标记 completed。
- 失败案例只打印安全字段；用假的敏感标记检查日志是否泄露，不能用真实密钥做测试。

每项对比预期与实际，最后汇总。任何不符合预期的案例都应让脚本以非零状态退出。

## 真实调用

离线案例通过后，分别询问教学模拟报价、公司资料，至少跑通一次完整工具往返。
确认最终回答中的数字和资料来自工具，且标明模拟。
记录实际轮数、工具次数、用量、耗时及人工检查结果；模型未调用工具时不能记为工具链路通过。
