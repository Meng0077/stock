# Stock Agent 前端简历表述草稿

这些内容是“完成对应验收后”的简历候选文案，不代表当前已经实现。每一条都必须能用代码、测试或演示证明后才能放入正式简历。

## 项目描述

基于 React、TypeScript 与 FastAPI 构建对话式、可追溯的股票研究 Agent 工作台：用户通过自然语言发起研究，服务端将消息归一化为内部研究上下文，前端分层呈现事实、推断、证据、数据时间、Decision Trace 和个人仓位风险；项目仅提供研究与假设分析，不包含交易下单能力。

## 分阶段候选项目要点

### FE02 完成后可用

- 基于 React + TypeScript 构建单轮对话式 Agent 研究页面，用户只需输入自然语言；使用可辨识联合类型管理完成、信息不足、失败与取消终态，将事实、推断、缺失信息和证据编号分组件呈现。
- 以固定 fixture 和可替换请求函数隔离模型随机性，覆盖输入校验、安全错误展示及旧请求响应覆盖等前端状态测试。

### FE03 完成后可用

- 设计 `RunTransport` 传输抽象，统一 mock 与 FastAPI 对话接口；在服务端隔离公开消息请求和内部研究请求，并结合 `AbortController`、本地请求序号和后端 `run_id`，避免慢响应污染当前研究结果。
- 建立 API 错误分层，区分浏览器网络错误、HTTP 请求校验错误和 Agent 公开终态，避免在页面暴露原始异常与敏感配置。

### FE04 完成后可用

- 构建证据与数据时间展示链路，关联文档来源、报告期、行情时间和宏观发布时间，明确标识 fixture、历史、延迟和冲突资料。
- 对模型说明采用 Markdown 解析与 HTML 清洗，并对引用 URL 执行可信来源校验；通过恶意协议和事件属性用例验证渲染边界。

只有真正实现 Marked、DOMPurify 和安全测试后，第二条才能写入简历。

### FE05 完成后可用

- 将确定性 Decision Trace、市场观点与个人仓位风险拆分展示，对比假设调整前后的集中度和命中规则，保证模型说明不能覆盖结构化风险结论。

### FE06/FE07 完成后可用

- 参考成熟 AI Chat 的事件处理思路，设计 `Transport → Parser → Reducer → Renderer` 流式架构；基于 `run_id` 和事件序号处理重复、乱序、取消与断线恢复，并以最终结果快照作为权威状态。
- 通过可控 Fake Transport 和浏览器端到端用例覆盖正常、信息不足、风险否决、取消、旧流回写和断线恢复，避免测试依赖真实大模型的随机输出。

## 推荐的最终三条版本

项目全部完成后，可从下面选择三条放入简历：

1. 基于 React + TypeScript 构建对话式、可追溯的股票研究 Agent 工作台，用户以自然语言发起研究，页面以类型化组件分层展示事实、推断、引用、数据时间、Decision Trace 与个人仓位风险。
2. 设计 `Transport → Parser → Reducer → Renderer` 前端事件链路，统一 mock、HTTP 与 SSE；结合 `AbortController`、`run_id` 和事件序号处理取消、重复、乱序及旧响应覆盖，并以最终快照保证状态一致性。
3. 建立 AI 输出安全渲染与确定性回归体系，对 Markdown 进行解析和 HTML 清洗，对引用执行可信 URL 校验，并使用 Fake Transport 覆盖信息不足、风险否决、断线恢复等故障路径。

## 面试口述版本

> 这个项目采用对话式输入，但不是简单把模型回答渲染成 Markdown。浏览器只提交用户自然语言，服务端把它归一化为内部研究请求；前端用 TypeScript 定义运行终态和结构化结果，把事实、推断、证据、决策和风险分别交给不同组件。网络层通过 Transport 抽象隔离 mock、HTTP 和后续 SSE，因此旧请求、临时 token 或模型自然语言不能覆盖正式的风险结论。
